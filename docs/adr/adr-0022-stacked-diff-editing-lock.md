# ADR-0022: 叠放预览采用试用校准效果，仅可编辑侧获得悬停锁

- **状态**：Accepted
- **日期**：2026-11-06（用户确认日；实施记录于 2026-11-07 追加）
- **取代**：部分取代 [ADR-0021](./adr-0021-stacked-diff-preview.md) 决策第 2 项的前景背景透明度及第 3 项的焦点锁范围；组件分层、仅左右错位和逻辑行对应不变。
- **相关**：[叠放 Diff RFC](../working/rfcs/2026-11-06-request-body-stacked-diff.md)、[组件契约](../../frontend/src/components/stacked-diff/README.md)

## 背景

独立示例试用后，用户确认初始前景过于通透，需要加重前景底色、稍微加强后景模糊。
同时明确焦点保护的意图是防止正在编辑的内容被悬停切换打断，而不是保护所有聚焦内容。
阶段一按任意焦点锁定整侧，会导致只读结果聚焦后无法悬停返回原始文本，与该意图不同。

## 决策

**采纳用户试用确认的叠放交互契约：前景背景 30% 透明、后景轻微模糊；只对宿主声明的可编辑侧建立悬停锁。**

1. 背景 alpha 只作用于底色，前景文字不降低透明度；具体模糊与动效默认参数由组件 README 维护。
2. `editableSide` 由宿主声明，默认 source；result 表示反向编辑场景，null 表示两侧均只读、不锁定。
3. 聚焦任何一侧仍使该侧进入前景，但只有可编辑侧的焦点 / 组合输入状态阻止自动悬停切换。
   只读侧聚焦和选区不产生锁，切换不销毁内容、不主动调用 blur。
4. 明确的用户切换、键盘 / 触屏入口以及已被阻止的悬停不重放规则保留。

## 后果

**正面**

- 前景内容更易读，后景仍能透出并表达层次；效果沿用实际试用结果。
- 编辑操作保持稳定，只读查看不妨碍通过悬停回到另一侧。
- 编辑能力和真实焦点分开建模，组件可用于两侧只读或反向编辑场景。

**负面**

- 只读内容选取后仍可能因悬停而退到后景，这是接受的展示行为；选区保留但不锁层级。
- 宿主必须正确声明编辑侧；通用插槽不能仅凭是否聚焦推断内容是否可编辑。

## 备选方案

### 任意聚焦均锁定

- 描述：延续阶段一对两侧标题、内容和操作的统一焦点锁。
- 拒绝理由：只读查看也会阻断悬停返回，超出了用户要求的编辑保护范围。

### 只按 source / result 身份硬编码

- 描述：永久只锁 source，不允许更换编辑侧。
- 拒绝理由：只能适应当前请求体编辑场景，不能支持反向编辑或两侧均只读的复用场景。
