# ADR-0023: JSON 行对齐保留真实草稿，用词法位置解析与语义 Diff 配对

- **状态**：Accepted
- **日期**：2026-11-07
- **取代**：无
- **相关**：[叠放 Diff RFC](../working/rfcs/2026-11-06-request-body-stacked-diff.md)、[ADR-0021](./adr-0021-stacked-diff-preview.md)

## 背景

原始请求体允许用户自由编辑缩进、空行或紧凑 JSON。`JSON.parse` 提供值但不保留词法位置；
仅将解析后的值重新序列化，得到的行号不能对应用户真实草稿。数组元素删除后，按下标配对
也会把后续元素误判为全部改写。对齐占位不能写回可编辑文本，否则光标和请求内容会被改变。

## 决策

**保留真实草稿，用 `jsonc-parser` 定位节点源码范围，复用现有 JSON 语义 Diff 的数组配对建立逻辑行映射。**

1. 严格 JSON 校验先于位置解析，不因解析器具备 JSONC 能力而放开注释、尾逗号或不完整 JSON。
2. 源行范围来自实际文本，结果行范围来自真实输出；删除痕迹只取被删节点的词法范围。
3. 紧凑 JSON 共享行的映射按行范围组合；没有源 / 结果行的一侧保留 null，不伪造行号。
4. 通用叠放组件仅消费行映射与滚动端口，JSON 位置解析依赖留在宿主适配层。
5. 映射只对可靠对应的成功输入快照生效；无效草稿或过期结果保留展示、暂停滚动联动。

## 后果

**正面**

- 不强制格式化用户草稿，也不将展示占位写进 textarea 的 value。
- 复用数组配对，删除头部或中间元素不导致后续内容的虚假 Diff。
- JSON 源码定位交给成熟解析库，避免另写一套字符串转义与括号扫描器。

**负面**

- 宿主新增 `jsonc-parser` 依赖，需要维护严格 JSON 与位置解析两步的一致性。
- 同一真实行上的多个字段无法按字符独立滚动，只能建立逻辑行 / 区间对应，这是接受的精度边界。
- 需要保留成功输入快照；重复字段、过深嵌套等无法可靠定位的输入要明确提示并暂停映射。

## 备选方案

### 每次输入后强制格式化

- 描述：将两侧统一为格式化 JSON，再按格式化行号对齐。
- 拒绝理由：会改写用户草稿、影响光标和输入过程；显示行不再对应真实编辑行。

### 自建正则或括号扫描器

- 描述：自行扫描文本定位对象键和值。
- 拒绝理由：JSON 转义、紧凑布局与嵌套结构要求完整词法解析，重新实现成本和错误风险更高。

### 只做逐文本行 Diff

- 描述：仅按行文本是否相等建立对应。
- 拒绝理由：缩进、空行和紧凑布局会制造噪声，也会丢失既有数组删除 / 改写配对语义。
