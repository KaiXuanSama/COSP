# ADR-0021: 叠放 Diff 预览分离通用交互与请求体业务

- **状态**：Accepted
- **日期**：2026-11-06
- **取代**：无
- **相关**：[RFC：请求体规则组左右布局与叠放 Diff 预览](../working/rfcs/2026-11-06-request-body-stacked-diff.md)

## 背景

请求体规则编辑器目前把原始文本与结果 Diff 横向并排，规则列表在下方。
预览区偏矮，规则、条件与预览之间的层次不够明确。用户已确认改为组内约 1:2 的左右布局：
左侧使用两张仅左右错位的叠放容器，右侧编辑规则，左侧高度跟随右侧并设最小高度。

叠放交互需要在悬停时切换前后景，但不能打断正在输入或选取的文本。
同时，该组件需要支持在其他项目复用，不能依赖供应商、协议或请求体规则执行。
两份内容还需逻辑行对应；仅同步滚动比例不能处理新增、删除后的文本位移。

## 决策

**将叠放预览拆成通用单容器与双容器组合组件；组合组件统一管理层级、焦点锁及基于行映射的协调，请求体业务在接入层提供。**

1. 单容器负责标题、操作、内容和提示的承载，以及前后景视觉状态；
   双容器组合负责统一的前景选择和交互协调，避免两个容器各自抢占前景。
2. 后景容器直接附加轻微模糊；前景背景约 66% 透明，文字、控件和光标保持清晰。
   两张容器仅左右错位，浮沉不交换左右位置。
3. 获得焦点的前景文本区阻止自动悬停切换；明确的用户切换操作仍可执行。
   层级变化保持内容挂载，保留编辑草稿、选区与滚动状态。
4. 通用组件消费文本展示、逻辑行映射与滚动接口；JSON 语义 Diff、源文本定位、
   后端预览、模板选择、格式化和复制由请求体接入层负责。转换结果保持只读。
5. 对齐以真实文本行之间的逻辑对应为准。浮沉透视和软换行产生的视觉偏差属于预期效果，
   不追求逐像素重合；展示占位不得写入原始文本或复制结果。

详细状态、布局、实施步骤和验收依据由相关 RFC 承载；正式组件接口在实现后由其目录
README 维护。本决策已经确认，组件实现尚未开始。

## 后果

**正面**

- 单容器可复用，双容器的协调逻辑只有一个状态所有者；请求体规则保持独立的业务边界。
- 规则编辑与预览位于同一工作行，原始文本和转换结果可以共享更高的阅读区域。
- 焦点优先于悬停，浮沉不会意外终止输入；行映射比滚动比例更准确地关联增删后的内容。

**负面**

- 需要新增行来源与对应模型，现有只读 Diff 树和滚动比例同步不能原样满足要求。
- 前景半透明会透出后景文字，模糊、阴影与错位距离需要实际校准以维持可读性。
- 悬停无法覆盖触屏与键盘，必须额外提供明确切换入口；两份内容持续挂载也增加渲染成本。

## 备选方案

### 继续并排双栏，规则列表放下方

- 描述：只调整间距或加高现有两栏。
- 拒绝理由：没有形成用户要求的左预览、右规则工作区，也无法提供错位叠放的层次效果。

### 每个容器独立管理是否处于前景

- 描述：容器自行响应悬停与焦点，再通过自身状态抬升层级。
- 拒绝理由：两个状态所有者可能同时抬升或反复互换，焦点保护和明确切换也难以协调。

### 在前景使用背景模糊

- 描述：由前景的 `backdrop-filter` 模糊它背后的内容。
- 拒绝理由：用户已明确选择后景容器自身轻微模糊、前景背景半透明；直接切换容器状态更符合已确认效果。

### 继续按两侧滚动比例同步

- 描述：保留现有基于总滚动高度比例的双向同步。
- 拒绝理由：删除或新增前部内容后，对应行在两侧的相对位置不同，比例不能保证逻辑行关联。
